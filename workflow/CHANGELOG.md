本文件记录工作流包的重要变化。未发布部分按改动批次保留过程；当前有效做法以 README 和正文为准，较早批次描述可能已由后续条目调整。历史版本不自动成为当前操作规范。

## [Unreleased]

- 将主线定位为公司通用 AI 辅助研发流程试行稿；保留模型自主、Context、关键决定、真实验证与项目责任边界。
- 收敛到 docs 下的原则、完整流程、工程规则和 AI 协作；模板按最小充分原则选择，项目差异通过现有指令或 PROJECT-RULES 记录。
- 从通用核心移除固定 FAST/STANDARD/CRITICAL、Gate 状态协议与个人工作区布局，不导入 Web 或 Ares 运行实现。
- 精简模板与三类教学示例，明确未执行/未验收内容；CI 改为文档结构、相对文件链接与入口检查。
- 旧根目录入口、试运行、研究及 Gate 模拟器通过固定基线保留，迁移位置见 [SOURCES](docs/SOURCES.md)。这是分支整理，不代表稳定发布或公司制度批准。

- 替代较早批次的单文档默认：功能说明为需求和导航入口，双端功能关联客户端实现、服务端实现及验证与验收；沿用已有格式，一端功能和小修按职责裁剪。
- 首页直接给 AI 使用指令、具体交付文件和双端 Mermaid 链路；工作指南补后续修改时的影响检查及需求、实现、契约和证据逐项核对。
- SPEC 改为功能入口，补三个分工模板与三个收藏配套例子；保留协议/配置/测试源码的权威位置。示例展示正常、权限、未知结果及限额变更，全部未执行。
- 对齐维护指令、帮助、工程规则、工具提示与历史去向；检查器纳入新增必要模板。未改业务项目、安装技能、运行产品或验证实际维护效率。

### 2026-09-10：Mermaid 详细流程与具体交付文件

- 首页用一张 Mermaid 图展示人与 AI 分工、实施条件、文档四部分的更新、验证和评审回流；工作指南链接同一图，避免重复维护。
- 明确普通功能默认交付“功能名.md”（如“收藏功能.md”），SPEC.md 是模板名；已有文件继续更新，独立小修按条件留在提单/PR。增加最终文件的四节结构，没有新增文档种类或目录要求。

### 2026-09-10：首页明确流程与提交物

### 整理前的未发布演进记录

以下条目属于整理前基线，不表示相关机制仍在当前主线启用。

- 完善 GitHub 首页的项目架构、双维度分级、交付产出与自动化边界，同步新手入口和 Issue/PR 协作说明。
- 分开判断文档规模与验证风险，兼容变化不再按关键词自动升级整套文档。
- 按任务精简 AI 输出、交付记录和外部目录，统一验收例外、修改后重验及无进展停止条件。
- 增加 Markdown 文档规范，保持单一 PRD/DELIVERY，并支持按 Client/Server 实例化 SDD 与验证记录。
- 增加代码、注释与复杂度规范，避免对每个方法强制填写易失真的 Big-O。
- 增加 FAST/STANDARD/CRITICAL 风险验证档位，明确白盒、冒烟、契约和独立 Review 的触发条件。
- 引入精简 AgentWorkspace 目录、存储边界、Stop/Resume/Cancel 与连续两轮无进展时停止当前路线的规则。
- 增加 2026 AI Harness 与轻量研发工作流研究报告，明确 v0.6 的精简优化方向及不引入的重型机制。
- 将 Requirement Intake 的事实、假设、Open/Blocked 分类和影响扫描合并进 Ready 与 AI 操作层，不新增默认报告。
- PRD 增加成功指标、可度量质量要求和假设/待确认状态；SDD 增加设计驱动与权威 Owner 边界。
- TEST-PLAN 增加阻断等级、计划基线、测试准入和暂停/恢复条件。
- DELIVERY 分离实现、验证和发布状态，并增加源码、构建、配置/Schema 和测试环境交付基线。
- 明确高风险 Hard Gate 的证据要求；独立 Review 按实际验证档位执行，执行者自检不能作为 CRITICAL 通过的唯一依据。
- 增加工作流 Gate 正反例回归夹具，阻止状态矛盾和缺失证据导致的 false-green。
- 升级 GitHub Actions checkout 运行时，消除 Node.js 20 弃用告警。
