# 1. 目标与背景

让新人不必先理解全部 PRD、SDD、TDD 和 Gate 术语，只需提供原始需求和工程位置，AI 就能按统一协议先检查工程、判断任务等级、选择最低文档、拆解功能并推进验证。

# 2. 范围与非目标

## 范围

- 新人五分钟入口。
- 编码 Agent 自动加载的简短项目指令。
- AI 的读取顺序、输出契约、停止条件和证据规则。
- 新任务、继续任务和最终 Align 三个可复制提示词。

## 非目标

- 不绑定单一 AI 模型或供应商。
- 不开发 AI 平台、IDE 插件或 CI 服务。
- 不声称未经真实新人测试即可证明可用性。

# 3. 验收标准

- AC-01：新人只读一个入口即可启动任务。
- AC-02：AGENTS 自动入口足够短，并指向唯一完整协议。
- AC-03：AI 首次输出包含工程证据、分级、最低产物、功能点、AC、风险和待决策项。
- AC-04：换 AI 后会重新检查当前状态，不只相信旧摘要。
- AC-05：缺少真实代码或测试证据时 Align 必须 Fail。
- AC-06：所有内部链接、Markdown 结构和关键指令检查通过。

# 4. 实现设计

采用三层结构：

1. `START-HERE.md` 面向新人，只解释如何启动和判断 AI 是否走偏。
2. `UPSTREAM-AGENTS.md` 面向支持项目指令的编码 Agent，保持短小并指向 `AI-PLAYBOOK.md`。
3. `AI-PLAYBOOK.md` 集中维护行为和输出协议；`prompts/` 只提供动态任务输入，避免重复系统规则。

该结构遵循“固定规则只写一次、动态上下文后置”的原则，减少指令漂移和上下文浪费。

# 6. Align Gate

`Pass`：入口、执行协议、三个提示词和 README 导航一致，关键规则断言全部通过。

限制：尚未由真实新人分别使用 Codex、其他编码 Agent 和普通聊天 AI 完成盲测，因此“能否减少上手时间和误操作”仍是待实证问题，不包装为已证明结论。

# 7. 下一轮试验建议

选择不了解本 SOP 的新人和一项真实 L2 任务，记录首次正确分级率、需要人工解释次数、AI 生成的无效文档数、Ready 用时和最终 Align 偏移数。根据结果删改协议，不继续凭想象增加提示词。
