# 背景与问题

需要避免需求、设计和实现长期偏移。“文档权威”可以强化规范，但如果任何文档都高于代码、测试和运行事实，过期文档本身会成为错误来源。

# 候选方案

1. 所有文档统一高于代码：规则简单，但无法处理文档过期和可执行契约。
2. 代码是唯一事实：能反映当前实现，但产品意图和决策理由会丢失。
3. 按信息类型定义权威：需要一张清晰映射，但能同时保留规范意图和可执行事实。

# 决定

选择按信息类型定义分层权威。PRD/SPEC 对需求意图和验收具有规范性权威，SDD/ADR 对关键设计和决策具有规范性权威，可执行接口、测试、代码和运行证据分别负责契约、实现与线上事实。

# 后果

- 正面影响：冲突可被分类，不会让过期文档或偶然实现自动成为全部真相。
- 代价：Gate 必须先判断冲突属于哪类信息。
- 后续动作：在 SOP 和模板中明确权威映射与偏移处理规则。

# 验证与复审条件

若实际试运行中多数冲突无法归类，或团队需要频繁维护重复来源，应合并信息类型并简化映射。
