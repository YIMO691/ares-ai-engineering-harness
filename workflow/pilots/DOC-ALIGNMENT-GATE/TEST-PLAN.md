# 1. 测试目标与范围

验证 Gate 能以较低成本发现真实偏移，并且不会要求 L1/L2 新增独立审批文档。

# 2. 测试策略

使用现有 L1、L2、L3 示例进行桌面演练；为每个示例注入一类偏移，检查 Gate 是否给出唯一处理路径。再用本功能自身文档完成一次完整对齐。

# 3. 需求与测试映射

| 验收项 | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 检查 README/SOP 流程 | Align 位于评审与 Done 之间 |
| AC-02 | 查询每类信息的权威来源 | 每类只有一个主来源或可执行来源 |
| AC-03 | 对 L1/L2 执行 Gate | 不要求新增独立报告或审批 |
| AC-04 | 注入五类偏移 | 能判定回到 Ready、Build 或补齐实现/验证 |
| AC-05 | 对三级示例执行 | 检查深度随等级增长 |

# 4. 场景

1. L1：将代码结果改为“空名称显示空字符串”，与 AC 冲突，应判定实现错误并 Fail。
2. L2：新增接口字段但 SPEC 未记录，应判定设计/契约偏移并 Fail。
3. L3：将文件保留期从 24 小时改为 7 天但 PRD 未更新，应判定需求变化并回到 Ready。
4. L3：实际使用异步任务但 ADR 仍选择同步，应判定设计决定过期并 Fail。
5. 任意等级：AC 标记完成但无测试或人工结果，应判定验证缺口。

# 5. 通过条件

- 所有场景都有明确判定和修正入口。
- L1/L2 只更新现有交付检查。
- Gate 不要求文档复制代码可自动表达的机械细节。
- 本功能的 PRD、SDD、ADR、模板修改和验证结果完成对齐。
