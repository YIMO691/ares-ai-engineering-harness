# 1. 目标与背景

项目较多时，用户难以快速找到常用项目。本次在项目列表增加收藏能力和“仅看收藏”筛选。

# 2. 范围与非目标

## 范围

- 用户可以收藏或取消收藏有访问权限的项目。
- 列表支持仅显示当前用户收藏的项目。
- 收藏状态跨设备保留。

## 非目标

- 不支持共享收藏夹、收藏排序或批量收藏。
- 不改变项目本身的权限和默认排序。

# 3. 用户流程与业务规则

1. 用户点击项目行的星标，系统保存当前用户的收藏关系。
2. 用户打开“仅看收藏”，列表只显示仍有访问权限的收藏项目。
3. 项目被删除或用户失去权限后，不再展示；残留收藏关系由后台清理任务处理。
4. 重复收藏和重复取消均返回当前最终状态，不产生错误提示。

# 4. 验收标准

- AC-01：收藏后刷新页面或更换设备，星标仍保持。
- AC-02：仅看收藏只返回当前用户有权访问的收藏项目。
- AC-03：连续点击或重复请求不会创建重复关系。
- AC-04：收藏接口失败时恢复原 UI 状态并提示重试。

# 5. 实现设计

- 新增以 `user_id + project_id` 为唯一键的收藏关系。
- 收藏接口采用幂等新增/删除；列表查询复用现有权限过滤，再按收藏关系筛选。
- 客户端先展示加载状态，服务端成功后更新本地缓存，失败则回滚星标。

## 异常、兼容与回滚

新表为空时等同于没有收藏，对旧用户行为无影响。功能入口可通过现有前端开关隐藏；回滚代码前无需迁移业务数据。
