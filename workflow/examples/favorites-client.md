# 收藏功能：客户端实现示例

[功能入口与 AC](L2-standard-feature.md) · [服务端实现](favorites-server.md) · [验证与验收](favorites-verification.md)。对应教学基线 A，方案未实现；符号用于演示如何定位，实际采用必须换成真实文件、符号和版本。

## 正常路径

AC-01 的拟定调用链：`FavoriteButton.OnClick` → `FavoriteController.SetDesiredState` → 共同契约的 `SetFavorite` → 确认响应 → 更新 `FavoriteViewState` → 刷新按钮。重开列表走 `ListFavorites`，持久结果属于服务端；本地状态只用于展示和缓存。

| 界面状态 | 触发及下一步 |
|---|---|
| 未收藏 / 已收藏 | 点击后记录当前操作身份与期望状态，进入提交中 |
| 提交中 | 暂停同一条目的重复点击；收到有效确认才更新最终状态 |
| 明确拒绝 | 显示可理解原因，保留最后确认状态；权限失效时同时刷新可见性 |
| 待确认 | 超时/断线进入；展示“正在确认”，走下方恢复路径 |

以上没有实际 UI 文件或截图。真实交付应补入口、界面创建/关闭及关键代码链接，保留已有人工补充；不凭空填写项目路径。

## 账户与权限

AC-02：请求身份来自登录会话；切换账户时清空该账户的展示缓存及界面订阅，不能把旧响应灌入新账户。旧账户操作状态按账户隔离存储，不能因界面清理而误称已取消服务端写入。

列表以服务端当前可见结果为准。客户端隐藏不可用按钮只是体验处理，服务端仍需在直接调用和列表查询处鉴权，见 [权限与查询](favorites-server.md#权限与查询)。

## 未知结果与恢复

AC-03：本例拟保留账户、条目、操作身份和期望状态，便于重开后恢复；具体存储和结果保留期尚未确定。

1. 写入超时只说明未拿到确认。客户端进入待确认，不直接回退并宣称失败，也不自动产生相反操作。
2. 用原操作身份查询。返回最终成功/拒绝时按结果更新；处理中继续按有限等待策略确认，查询不到仍可能是请求迟到。
3. 无法在约定窗口内确定结果时保留未决状态与恢复入口，先核实服务端机制，不无限轮询或换身份重写。恢复策略与过期语义未落实前，本场景不能验收。
4. 响应到达时核对当前账户、条目、操作身份及状态版本；关闭的界面不继续渲染。取消订阅不等于取消服务端操作。多设备或后续操作导致的版本冲突仍须真实协议支持，不能只靠本地计数解决。

定位超时先收集脱敏操作关联、发送/超时/确认顺序、服务端最终状态与数据，不仅看一个弹窗。检查见 [V-03](favorites-verification.md#v-03-响应丢失与迟到)。
