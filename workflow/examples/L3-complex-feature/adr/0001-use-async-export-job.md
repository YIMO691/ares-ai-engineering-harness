# 背景与问题

大报表生成时间可能超过网关请求时限，并消耗显著 CPU、内存和数据库连接。需要让用户可靠获得结果，同时控制重复提交和系统容量。

# 候选方案

1. 延长同步请求：实现简单，但连接易超时，无法可靠恢复，也难以展示进度。
2. 异步任务和导出中心：增加任务状态与清理机制，但可以限流、重试、观察和恢复。
3. 客户端分页拉取后本地生成：降低服务端文件生成成本，但暴露更多数据接口，权限和浏览器资源风险更高。

# 决定

选择异步任务和导出中心，因为它能隔离长时间工作，并为限流、恢复、进度和审计提供稳定边界。

# 后果

- 正面影响：用户不依赖长连接；任务可追踪、可限流、可恢复。
- 代价：需要维护状态机、执行器、对象存储、过期清理和容量监控。
- 后续动作：建立排队时长、失败率和存储用量告警。

# 验证与复审条件

通过故障注入和容量测试验证。若未来所有导出都能稳定在同步时限内完成，或平台提供统一导出服务，应重新评估该决定。
