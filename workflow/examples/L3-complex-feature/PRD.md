# 1. 需求结论

允许有报表查看权限的用户提交大数据量导出任务，在后台生成 CSV 文件，并在完成后从导出中心限时下载。

# 2. 背景与目标

当前同步导出在数据量较大时会导致请求超时，用户无法判断任务是否仍在执行，也容易重复提交。

## 目标

- G-01：导出过程不占用长连接，用户可查看进度和最终结果。
- G-02：导出的字段和数据范围严格遵循提交时用户权限。
- G-03：失败任务可理解、可重试、可定位。

## 非目标

- NG-01：本期不支持定时导出和邮件附件。
- NG-02：本期仅支持 CSV，不提供自定义列模板。
- NG-03：不保证在用户失去权限后仍能下载历史文件。

# 3. 用户与场景

报表管理员在筛选数据后提交导出，可以离开页面；稍后在导出中心查看排队、执行、成功或失败状态，并下载仍在有效期内的文件。

# 4. 用户流程与业务规则

1. 用户选择筛选条件并提交导出。
2. 系统校验权限、筛选参数和并发限制，返回任务 ID。
3. 用户在导出中心查看状态。
4. 成功后提供一次性签名下载地址；文件保留 24 小时。
5. 失败任务展示可理解的错误类别，允许用户重新提交。
6. 同一用户在 10 秒内提交完全相同的请求时返回已有未完成任务。

# 5. 功能需求

| ID | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| FR-01 | 创建异步导出任务 | Must | 校验权限、筛选条件和并发限制 |
| FR-02 | 查询本人任务列表与状态 | Must | 不得查看其他用户任务 |
| FR-03 | 下载成功文件 | Must | 下载时再次校验权限，地址短期有效 |
| FR-04 | 失败分类与重新提交 | Must | 不自动无限重试 |
| FR-05 | 到期文件清理 | Must | 任务记录保留，文件删除 |

# 6. 验收标准

| ID | 对应需求 | 可验证结果 |
| --- | --- | --- |
| AC-01 | FR-01 | 提交后 2 秒内返回任务 ID，不等待文件生成 |
| AC-02 | FR-02 | 用户只能看到自己提交且当前有权访问的报表任务 |
| AC-03 | FR-03 | 成功任务可下载正确 CSV；越权和过期下载均被拒绝 |
| AC-04 | FR-04 | 可重试错误与不可重试错误展示不同结果，不产生重复文件 |
| AC-05 | FR-05 | 24 小时后文件不可下载，任务历史仍可查询 |

# 7. 依赖、风险与待确认项

- 依赖对象存储生命周期和签名 URL 能力。
- 上线前需要确认单用户并发上限和单文件最大行数。
- 含敏感字段的报表必须完成安全评审。
