# 按需参考：异步导出的设计与验证

虚构教学设计，没有产品代码、测试或发布结果。本页是按问题查阅的设计片段，保留取舍和失败处理，未覆盖完整客户端实现；不能直接作为完整双端功能交付。需要关联文档的写法时，从 [收藏功能入口](../L2-standard-feature.md) 阅读。

## 需求与边界

假设用户希望提交报表后离开页面，稍后查看本人任务并下载 CSV。教学约定：提交不等待生成，正常条件下 2 秒内返回任务标识；文件保留 24 小时；同用户 10 秒内重复提交相同请求复用未完成任务。这些数值不是通用标准。

需要同时满足：任务与下载权限隔离、撤权后拒绝下载；执行器重启可恢复，结果不会重复发布；内容和到期清理正确。本次不做定时导出、邮件附件或自定义列。

未决：数据规模、并发、计时边界与统计口径、后台授权语义、CSV 字段、到期起算点和恢复目标。缺少这些条件就不能宣布性能或发布就绪。

## 实现说明

### 选择与运行关系

| 方案 | 适用条件与代价 |
|---|---|
| 请求内同步生成 | 数据量可控且实测满足等待约定时较简单；不满足本例当前“离开后继续执行”的要求，采用前需真正修订需求 |
| 复用持久化后台任务 | 能支持跨请求查询和恢复；增加认领、去重、权限、文件一致性与清理成本，持久化本身不保证不重复发布 |

在上述教学需求及“已有后台设施”的假设下，拟选第二种；实际设施缺失或成本变化时重新比较，不因此自建调度平台。

1. Client 提交参数，请求服务校验权限并登记/复用任务，返回标识；生成文件留给后台。
2. 执行器认领任务、写临时结果，检查认领仍有效后发布。任务数据库与文件存储不是天然的同一事务；写文件后更新状态前崩溃，需要明确对账和恢复方式。
3. Client 查询本人任务；请求服务在下载时重新鉴权后回传文件。本例不让客户端直接访问存储。实际采用直链时，另查撤权与地址失效语义。

边界和关系不清时可据此画 C4；部署、运行和风险可按 arc42 检查；上表的理由与复查条件即可承载本次决策，无须再建立三种方法各自的文档。

### 失败、部署与兼容

- 提交响应丢失时先按同一次业务提交身份查询/复用。10 秒去重窗口不能解决窗口外仍未知的结果；身份、保留期限和窗口外处理须补约定，不能盲目新建任务。
- 后台使用提交时权限快照还是执行时复查仍待决定；下载时重新鉴权。日志不记录导出正文或可复用下载地址。
- 将请求服务、执行器、任务库和文件存储映射到真实设施，核对权限、独立重启和访问关系；逻辑图不等于部署图，也不证明高可用。
- 发布前确认旧同步入口和客户端、任务数据兼容、执行器并存及未完成任务处置。回退程序不等于恢复数据和文件，兼容回退或前滚方案需实际验证。

## 验证与遗留

以下是计划，全部未执行：

| 场景 | 观察依据及检查边界 |
|---|---|
| 暂停生成后提交，另测代表性负载 | 提交不等待文件；仍须分解网络、权限、存储和排队耗时，不能只凭后台架构宣布达到 2 秒 |
| 另一账户查询、本人撤权后下载 | 在实际查询及下载路径拒绝越权；按钮隐藏不能证明权限成立 |
| 重复/并发提交及窗口外未知结果 | 核验真实唯一约束与业务身份；窗口内通过不外推无限期去重 |
| 写临时文件后、发布前中断并恢复 | 先证明故障点发生，再检查任务/文件一致、认领归属和无重复发布 |
| 独立 CSV 样本及到期清理 | 预期来自已约定字段和独立样本，不能由同一导出函数生成；失败与过期处理符合最终规则 |

当前缺少实际实现、环境及上述未决契约，无业务验收或独立评审证据。若把权限查询改成缓存以改善耗时，需要同时复查撤权行为和下载路径，不能只验证更快。

需要发布时，在项目原记录明确提交耗时、积压恢复、权限异常和清理的观察范围/时段、接手人与处置权限。无相关安排时不把本例当发布批准；观察规则见 [工作指南](../../docs/WORKFLOW.md#发布后的观察与反馈)。
