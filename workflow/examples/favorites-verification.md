# 收藏功能：验证与验收示例

[功能入口与 AC](L2-standard-feature.md) · [客户端实现](favorites-client.md) · [服务端实现](favorites-server.md)。本页演示计划与结果如何关联，**全部未执行**，没有业务代码、测试环境、运行版本、独立评审或验收批准。

## 范围与基线

范围为教学基线 A 的 AC-01～03，B 的 AC-04 单独列出待定重验。真实采用后需登记客户端、服务端、协议/配置和场景版本，链接自动化测试名、CI 或脱敏人工证据；此处不伪造文件路径和证据链接。

## V-01 设置与取消

对应 [AC-01](L2-standard-feature.md#需求与边界)、[客户端正常路径](favorites-client.md#正常路径) 和 [服务端业务与数据](favorites-server.md#业务与数据)。

- 前提：两个有权限的内容、独立测试账户、初始无收藏。
- 操作：设置收藏 → 重新打开/重新登录读取 → 重复设置 → 取消 → 重复取消；另用两个并发请求设置同一条目。
- 预期：显示与服务端最终结果一致；最多一条账户/内容记录，取消后无记录；重复操作不产生额外效果。
- 检查层次：端内检查验证状态迁移及唯一约束分支，联调检查真实身份、序列化、持久化和界面链路。只 mock 服务响应不能证明持久结果。
- **实际：未执行**。无证据支持幂等或持久化成立；并发相反意图须补语义后另验。

## V-02 权限与隔离

对应 [AC-02](L2-standard-feature.md#需求与边界)、[客户端账户与权限](favorites-client.md#账户与权限) 和 [服务端权限与查询](favorites-server.md#权限与查询)。

- 前提：A/B 两账户、允许后再撤销的内容权限。
- 操作：匿名直调、伪造账户参数、B 查询 A 的操作身份、A 撤权后查询列表/重复添加/取消，客户端发送后切换账户再接收旧响应。
- 预期：非法访问不泄露或修改另一账户数据；撤权内容不可见且不能添加，仍可取消自己的旧收藏；旧响应不能污染新账户界面。
- 检查层次：直接接口/数据检查与客户端事件检查共同覆盖；只看按钮是否隐藏不足以证明授权正确。
- **实际：未执行**。没有权限隔离结论。

## V-03 响应丢失与迟到

对应 [AC-03](L2-standard-feature.md#需求与边界)、[客户端恢复](favorites-client.md#未知结果与恢复) 和 [服务端操作结果](favorites-server.md#操作结果与恢复)。

- 故障 A：在实际提交成功后丢弃写响应。先证明故障点确实发生，再检查客户端进入待确认、查询同一次操作后恢复，最终数据无重复。
- 故障 B：延迟写入到“查询未找到”之后才执行。预期不能在第一次未找到时宣称失败或发送相反操作；观察迟到写入和恢复后的状态。
- 故障 C：提交前中断、事务后进程重启、界面关闭重开、查询失败、同身份不同请求。核对两端说明中的对应分支和副作用。
- 待定：结果过期、多设备冲突、状态版本和等待策略的契约尚未落实，先补预期再执行，不能通过改测试目标制造成功。
- **实际：未执行**。只模拟超时回调不能证明发生过“写入成功而响应丢失”；无实际故障点和最终数据证据就不能验收恢复。

## B 的重验

B 仍为 [拟追加需求](L2-standard-feature.md#后续提单怎样修改)，没有覆盖它的旧业务证据。

| 场景 | 预期或待定 | 实际 |
|---|---|---|
| 99 条添加新的第 100 条 | 成功；界面与数据一致 | 未执行 |
| 100 条添加新条目 | 拒绝且数据不增加，客户端正确结束等待 | 未执行 |
| 100 条重复设置已有条目 | 当前权限仍有效时成功，不占新名额 | 未执行 |
| 取消一条后再添加 | 可用名额恢复；还需检查取消重复调用 | 未执行 |
| 99 条时两实例并发添加不同条目 | 最多一条新增成功；不能仅测顺序调用 | 未执行 |
| 旧账户超限、已撤权条目 | 计数及迁移策略待业务决定 | 预期未定，不能验收 |
| 旧客户端收到新增拒绝 | 兼容策略落实后检查提示、状态和恢复 | 未执行 |

V-01 的唯一约束结论即使将来通过，也不覆盖“不同条目争抢最后名额”；V-03 若返回语义或事务路径变化须重验。对未改路径是否可复用旧证据，应结合真实差异和版本判断，本例没有可复用的执行记录。
