# 贡献指南

## 开始之前

- 使用问题选择“使用问题”Issue 表单。
- 明确错误选择“规范或模板缺陷”。
- 流程优化选择“流程优化建议”，并提供真实场景和影响。
- 不在 Issue、PR、提交或示例中放入秘密、生产数据、个人信息或未脱敏公司材料。

## 变更原则

1. 优先减少重复和无效成本。
2. 新增强制项必须对应已发生风险、法规安全要求或重复出现的交接失败。
3. 同一规则只保留一个权威来源，其他文件使用链接。
4. L1/L2 不因模板增加而自动变重。
5. 没有真实实现或验证证据时不得将 Align 标为 Pass。

## 开发流程

1. 从 `main` 创建短生命周期分支，建议使用 `docs/`、`fix/` 或 `workflow/` 前缀。
2. 更新 SOP 或模板时，同时检查 README、示例、AI 操作层和 GitHub 模板是否受影响。
3. 本地运行：

   ```powershell
   pwsh ./scripts/validate-workflow.ps1
   ```

4. 使用 PR 模板说明问题、证据、影响和 Align 结论。
5. 至少由 CODEOWNERS 中的维护者评审后合并。

## 提交建议

- 使用聚焦且可回滚的提交。
- 提交标题使用祈使句并说明结果，例如 `Add scoped authority checks to Align Gate`。
- 纯移动或重命名尽量与内容修改分开，便于评审。

## 流程改进结论

维护者应将建议标记为接受、试验、拒绝或暂缓，并说明理由。试验中的变化应有范围、观察指标和复审时间。
