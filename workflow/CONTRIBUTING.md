# 贡献指南

优先解决实际使用中的重复记录、遗漏和交接困难。用户从 [README](README.md) 开始；本文用于维护 SOP。责任见 [CODEOWNERS](.github/CODEOWNERS)，讨论遵循 [行为准则](CODE_OF_CONDUCT.md)。

## 提出问题或修改

使用 [Issues](https://github.com/YIMO691/Workflow-SOP/issues) 的使用问题、规范缺陷或流程优化入口，提供版本、场景、预期与实际情况；已有讨论直接补充，不为每次改动强制新建 Issue。

1. 核对远端、分支、未提交改动和 PR。新工作从当前 main 建聚焦分支；授权继续的变更在原分支完成，不覆盖他人工作。
2. 找到权威正文，只修改受影响的规则、模板、例子及引用。优先删减重复内容，不为新术语增加文档层级。
3. 规则变化说明实际用途与维护代价；退役路径和重要锚点在 [来源与历史](docs/SOURCES.md#旧入口去向) 登记固定基线及当前去向。
4. 完成下方适用检查，按 [PR 模板](.github/PULL_REQUEST_TEMPLATE.md) 说明问题、改动、影响、真实验证和限制。
5. 按反馈修订；未经明确授权不合并或发布，不 force push。维护者可接受、限定试用、暂缓或拒绝，并说明依据。

## 文档职责与写法

| 内容 | 唯一维护位置 |
|---|---|
| 交给 AI 的使用入口 | README：任务指令、阅读入口与预期结果 |
| 执行、功能文档维护、完成与交接 | 工作指南；保留一套约定，参考文档链接回来 |
| 代码、契约、诊断与验证判断 | 工程规则，按问题查询 |
| 长期工具接入与排查 | AI 工具接入参考，避免复制日常流程 |
| 日常功能记录 | 功能入口关联两端实现与验证；项目共用信息缺失时才补项目约定 |
| 例子、技能与来源 | 具体写法、适用条件、固定来源和证据边界；不写成必经阶段 |

开发留痕默认在原任务及对应功能文档完成；文档正文解释当前功能，重要变化引用提单/PR。已有项目格式和记录可以继续使用，双端功能按职责维护关联记录，不重复新建 PRD、SDD、测试计划或交付报告。详细维护要求只在 [工作指南](docs/WORKFLOW.md#维护功能说明) 保留。

Markdown 使用一个一级标题、UTF-8 无 BOM 和 LF；标题、段落、表格、列表与围栏之间留空行。内部使用相对链接，标题或路径变化时核对引用。示例明确虚构性质，计划与已执行结果分开，保留人工有效内容。命令写明工作目录和前提，不把占位符写成可执行指令。

引用外部方法保留版本、实读范围、适用限制及复查触发，成熟机构名称不构成效果证明。GitHub README/模板机制不要求所有正文使用同一章节模板；原核对见 [来源记录](docs/SOURCES.md#github-文档与协作模板的定向核对)。

## 验证方式

需要 PowerShell 7。在仓库根目录执行：

```powershell
pwsh -NoProfile -File scripts/validate-workflow.ps1
```

检查 Markdown 非空、单一一级标题、围栏、相对文件目标和必要入口；不验证锚点、外部网址、YAML 表单语法、AI 加载或业务行为。根据实际改动补查：

- 路径/标题：内部锚点、受影响引用与旧入口去向。
- 规则/模板/示例：条件一致、记录可追溯，预期与实际区分。
- 排版/图表：渲染后的结构和必要图形。
- Issue/PR 模板：GitHub 语法及输入提示，不预填通过或未经授权的分派。
- 检查器：有效包与相关损坏输入，确认入口整合未放过缺失内容。

[CI](.github/workflows/validate.yml) 执行同一文档检查。GitHub 表单需要进入默认分支才供新建使用；本地语法检查不等于线上验证。项目测试、安全、评审和发布仍由项目自己的要求决定。

## 敏感内容与许可

只提交通用、获准共享的内容，不上传商业源码、认证、本地配置、原始日志和生产数据。敏感问题按 [安全说明](SECURITY.md) 私密反馈。引用不扩大原资料访问及再分发权限；本仓库未选择开源许可证。
